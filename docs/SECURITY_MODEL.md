# Security model

## Scope

BioDepot Workbench separates planning and review from execution. It can inspect
catalogs, compose graphs, validate parameters, and render bundles without
granting a browser or agent arbitrary command execution. Execution is an
explicit, separately gated operation.

This repository defines application contracts. It does not provide a production
identity provider, reverse-proxy configuration, host inventory, network access
rules, or credential distribution mechanism.

## Trust boundaries

### Browser and HTTP clients

Requests are untrusted. Parameters are validated against graph schemas, output
paths are bounded by configured roots, archive members are generated by the
server, and workflow execution is denied until the associated graph,
parameters, paths, and execution location have been reviewed.

When deployed behind an authenticating proxy, the proxy must remove incoming
identity headers before adding its verified identity. Direct deployments should
use the anonymous/single-user mode or add an application authentication layer;
the presence of a request header alone is not proof of identity.

### MCP clients and agents

MCP tool annotations communicate whether an operation is read-only, creates an
artifact, can execute code, or requires human approval. They are guidance for
clients, not an enforcement boundary. The service independently verifies
review tokens, run ownership, parameter hashes, execution locations, and
preflight state.

### Persistence

Conversations and runs are associated with a normalized owner identity.
Cross-owner reads, updates, forks, and run links are denied. SQLite is the local
default; a production database remains responsible for encryption, backup,
retention, and database-level access controls.

### Filesystem and execution locations

The location contract distinguishes server-visible, caller-visible,
remote-visible, and scheduler-visible paths. A path valid at one location is
not silently treated as valid at another. Remote inputs are copied only through
explicit adapters, subject to size limits, and preflight reports blockers rather
than guessing at reachability.

Generated bundles are reviewable artifacts. Server execution requires a valid
review record and successful preflight for the unchanged graph, parameters,
bundle, and location. Caller-managed locations return instructions rather than
causing the server to execute on the caller's machine.

## Secret handling

- Credentials are supplied at runtime through the deployer's secret mechanism;
  they are not stored in this repository.
- Local model configuration, environment files, private keys, databases, run
  outputs, and large biological files are ignored by Git.
- API/MCP payloads should carry credential references or connector identifiers,
  not literal secret values.
- Logs and validation records store hashes and bounded metadata rather than
  source file contents or tokens.

## Network behavior

Local nf-core harvest reads only the selected checkout. Remote harvest fetches
known metadata files with time and size limits; network tests are opt-in.
Executing generated workflows may invoke external tools and containers and must
be reviewed under the deployer's own network and supply-chain policy.

## Public-release scrub

`python3 scripts/scrub_public_release.py` walks the candidate tree and fails on
forbidden directories, private absolute paths, named internal infrastructure,
identity-provider configuration, private data markers, common credential
formats, or symbolic links. It is run before release validation and should be a
required continuous-integration check.

The scrub complements, but does not replace, dependency scanning, secret
scanning, code review, and deployment-specific threat modeling.
